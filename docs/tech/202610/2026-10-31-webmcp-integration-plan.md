# xiaohui.cool WebMCP 接入技术方案

状态：P1 代码已实现并完成本地自动验证，默认关闭，未部署。原生浏览器与真实 Agent 验收待完成，详见[优化记录](./webmcp/06-optimization-record.md)。

## 1. 决策

在现有 Quartz 静态站上增加渐进增强的 WebMCP 入口。第一版开放 `search-notes`、`read-note`、`get-current-note` 三个读取工具，复用现有公开内容产物与 FlexSearch，不引入模型服务、API Key、数据库、向量检索或独立 MCP Server。

按模块隔离实施：数据契约、构建期产物、浏览器数据访问、检索、阅读、页面上下文、WebMCP 协议适配、Quartz 装配分别建目录。业务代码不依赖 WebMCP，协议适配不直接操作 DOM，UI 不通过模拟工具调用完成普通搜索。

现有 `llms.txt` 与 Markdown 入口继续服务站外读取。WebMCP 的增量是支持 Agent 在打开的网站中检索、获取当前阅读上下文，后续再把结果呈现到页面。它不保证提高搜索收录，也不会自动让所有聊天客户端发现网站。

## 3. 范围与顺序

1. **P0：兼容性验证。** 用真实文章核验目标浏览器与 Agent 对当前 API 的支持，确认注册、发现、调用、返回、注销；不能用 mock 替代真实集成验收。
2. **P1：三个读取工具。** 构建轻量文章目录，复用搜索库；在首页、文章页、列表页接入，禁用或失败时保持普通站点可用。
3. **P2：页面协作。** 可选增加 `show-search-results` 与 `get-related-notes`；复用业务服务并单独设计可见 UI，不混入 P1。

本方案和实现范围不扩展到内容写入、自动发文、投资操作或跨域 Agent 集成。实现支持正文分页与有可靠源码映射的章节读取；特殊标题仍明确降级。

## 4. 核心验收目标

- 支持环境能从首页搜索“上下文工程”，读取命中文章并返回正式引用链接；文章页能准确报告当前文章。
- 不支持环境不请求新增 Agent 索引、不抛出未处理异常，搜索、导航、分享与阅读继续工作。
- 首次工具调用前不下载新增全文索引；同一会话内共享数据与索引，不随 SPA 切页重建。
- 长文可分页读取；章节使用构建期真实标题 ID，避免中文标题重算与同名标题误匹配。
- 连续切页、失败重试、并发取消及部署更新不产生重复工具、过期文章结果或永久失败缓存。
- 浏览器原生能力、polyfill 能力与 Agent 接入能力分开报告，未实测项保持明确标注。
