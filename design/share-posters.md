# 文章分享图

分享面板保留「二维码短卡」，并提供「长文分享图」。两种版式共用预览、保存图片、系统图片分享和不支持系统分享时的保存回退。默认仍是短卡。

## 内容与版式契约

- 短卡沿用标题与短描述，长图读取当前文章正文的真实 DOM，按原文顺序呈现，不使用 description 代替正文，也不自动生成摘要。
- 文章标题与晓灰站点标识始终保留。署名只来自文章已有的 `frontmatter.author`，支持字符串或字符串数组；不把 SEO 元数据里的站点名后备值当作作者。
- 长图保留段落、小标题、列表、引用和代码的基本结构。内容适配画布高度，约 800 字是自然内容块收尾的参考，不要求在固定字符处截断。额外的高度保护用于极长段落、代码和特殊内容。
- 未展示完时，渐隐只覆盖正文结尾，并附继续阅读提示。下方独立的二维码、阅读全文提示及站点信息保持清晰，二维码指向当前页面 canonical URL。
- PNG 在浏览器本地生成，不上传正文。颜色、字体取自 `quartz/design/tokens.ts`；导出采用浅色纸感，便于跨应用阅读。代码用等宽字体；正文用 CJK 友好字体。
- 预览按面板宽度展示，长图通过面板纵向滚动阅读，不把整张长图缩进一个固定高度的小框。

## 生命周期与回退

- 每种版式独立缓存，一篇文章最多保留两张图片；重复选择复用结果。
- 切换版式、关闭或重新打开面板、触发新操作后，较早的异步完成不能覆盖当前预览、状态或触发迟到的下载。
- 生成失败不会永久缓存失败结果，保存或切换版式可以重试；复制链接始终可用。
- 只有已缓存的图片可在用户点击的同步激活期间尝试系统分享。生成尚未完成、系统不支持、微信内浏览器或系统分享失败时，显示图片供保存或长按。取消系统分享不视为成功。
- SPA 离开文章时清理监听器、面板与对象 URL。离开后才完成的图片也立即释放。

## 验证

自动测试通过 `npm test` 执行，包括长图内容与排版边界、实际 SSR 署名和真实 inline 脚本的异步生命周期。设计契约与类型/格式检查仍使用 `npm run check:design` 和 `npm run check`。

`npm run test:share-browser` 使用 Chromium 对真实组件执行浏览器验收，解码导出的 PNG 二维码并保存 320px / 390px / 桌面截图。首次运行需要 `npx playwright install --with-deps chromium` 和可显示中文的字体。CI 在独立只读 Ubuntu 作业运行这些测试并上传 `share-posters-<SHA>` 证据，不部署网站。详情见 [浏览器测试说明](../tests/browser/README.md)。

真实浏览器还应检查：

1. 短文、接近阈值、超长文章与超长单段，中文与混合文本。
2. 小标题、嵌套列表、引用、代码与特殊内容无重叠、溢出或字符裁切。
3. 320px、390px 和桌面面板；浅色和深色页面上的预览与键盘焦点。
4. 两种图片的保存、系统分享/取消与不支持时的回退。
5. 反复切换、关闭重开、生成失败后重试和 SPA 离开。
6. 实际导出 PNG 的正文可读性、清晰的阅读全文区域，以及二维码解码结果等于 canonical URL。

## 真实项目内容复验

浏览器集成测试可通过 `SHARE_QA_SITE_DIRECTORY`、`SHARE_QA_ARTICLE_PATH` 和
`SHARE_QA_ARTICLE_TITLE` 指定新构建的真实文章。CI 另构建原有 content vault，
使用《DDD》验证真实正文、移动端预览、保存下载及完整 canonical URL 的二维码。
中文 canonical 的预期值通过标准 URL 解析规范化，不把 URI 与百分号编码的等价表示
误报为二维码指向不同地址。包含 Mermaid 的文章使用生产配置中的官方 CDN SDK 字节；
测试不以空脚本或伪造 Mermaid 实现代替实际运行。

真实《DDD》PNG 已视觉检查段落、小标题、列表、引用、自然收尾与渐隐、独立二维码。
这不覆盖全部文章，也不改变现有 Canvas 的简化边界：行内强调、图片、公式和表格
的原版式仍未完整保留，真实 OS 分享面板仍待实机验证。这些边界不属于本 issue 的基本块结构验收；不将此次通过称为完整排版保真或真实 OS 分享验收。

## 开源方案调查与最小自定义范围（2026-10-10）

本节补齐 PR 审查要求的选型证据。此次调查实际读取固定发布 tag 的官方 README、
源码发行包与 npm 元数据，并在当前 content 构建的真实《DDD》上运行 PoC，
不是按星数选择，也不是声称截图 SDK 无法使用。

| 方案                                                                           | 许可证与维护核对                                                                     | 集成方式与边界                                                                                                                                          |
| ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [html-to-image 1.11.13](https://github.com/bubkoo/html-to-image/tree/v1.11.13) | MIT；npm 版本元数据修改日期 2025-04-19；本次读取其固定 tag，而非据此保证当前维护频率 | 浏览器内复制 DOM/CSS，通过 SVG foreignObject 绘制；发行 JS 实测 20,562 B。官方 README 说明会嵌入字体和图片，以及 tainted canvas、巨大 data URI 的限制。 |
| [html2canvas 1.4.1](https://github.com/niklasvh/html2canvas/tree/v1.4.1)       | MIT；npm 元数据修改日期 2025-11-13，不等于 1.4.1 的发布日期或新版本承诺              | 浏览器内解析 DOM/CSS 到 Canvas；压缩发行 JS 实测 198,689 B。官方 README 明确不是原生截图、CSS 支持不完整，也不能绕过跨源资源策略。                      |
| 现有原生 Canvas + [qrcode](https://github.com/soldair/node-qrcode)             | 沿用项目现有 QRCode SDK 与浏览器 API，不自研二维码编码器或完整 HTML/CSS 引擎         | 只实现原文基本块摘录、自然收尾、有限测量与品牌图层组合；复用设计 token、Intl.Segmenter、字体、分享面板和保存回退。                                      |

真实 PoC 位于 [renderers.poc.mjs](../tests/browser/research/renderers.poc.mjs)，
运行命令：

```sh
SHARE_QA_SITE_DIRECTORY=.quartz-cache/share-production \
SHARE_QA_ARTICLE_PATH=program/学习-思考-冷静/DDD.html \
node tests/browser/research/renderers.poc.mjs
```

命令使用两个固定版本的官方发行 JS，只在显式运行 PoC 时下载，不作为生产依赖。
它在本地服务真实构建页面，保留公开资源内容、阻止分析服务，分别导出全文和按
顶层内容块收尾的约 800 字版本。输出 PNG 和结果 JSON 到
`test-results/renderer-research/`，异常记录为失败，不改写为通过。

| 方案                  | 实际正文 PNG        | 开头约 800 字 PNG            | 实际用时（全文 / 摘录） |
| --------------------- | ------------------- | ---------------------------- | ----------------------- |
| html-to-image 1.11.13 | 720×9160，1571049 B | 720×4016，943 字符，683447 B | 17.693s / 7.609s        |
| html2canvas 1.4.1     | 720×8472，1489761 B | 720×4018，943 字符，670537 B | 7.463s / 4.021s         |

两种 SDK 在本次 Chromium 实验中均成功，未出现横向溢出。该成功不能推广为
Safari、微信内浏览器、所有跨源文章或完整 OS 分享已验证。页面的动态 Mermaid
渲染使全文 DOM 字符数随渲染时点不同，PoC 字符数不能用于业务质量比较。

本 issue 要求的是去控件、按原文顺序的有限摘录与独立清晰二维码，不要求原版式截图。
上述 SDK 解决 DOM 光栅化，仍需项目自己处理自然内容边界、超长单段、渐隐区域、
手机阅读字号、署名来源及二维码保留空间；全文截图实测高达 8,472–9,160 px。
完整截图再像素裁切会从内容中间截断，无法直接满足自然收尾契约。PoC 的有界 DOM
准备也验证了 SDK 不会自动实现这些摘录规则。

因此本次保留已通过真实文章验证的基本块 Canvas 路径，自定义范围限定为这些
业务规则和少量品牌图层，复用 QRCode SDK 与原生 API；不扩展成通用 HTML/CSS
渲染器，不承诺保留图片、行内强调、公式和表格原版式。为现有有限呈现另引入完整
CSS/字体/图片复制管线会增加资源重取、跨源处理和额外光栅化路径，而本 issue
不使用其主要优势。这里是对本次范围的取舍，不是“库不能截图”的结论。
如果后续要求完整排版保真，优先基于本次成功 PoC 复用 SDK，不能继续用此次有限
Canvas 实现冒充完整保真；届时还需实机与跨源资源验证。
