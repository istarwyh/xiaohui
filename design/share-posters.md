# 文章分享图

分享面板保留「二维码短卡」，并提供「长文分享图」。两种版式共用预览、保存图片、系统图片分享和不支持系统分享时的保存回退。默认仍是短卡。

## 内容与版式契约

- 短卡沿用标题与短描述，长图读取当前文章正文的真实 DOM，按原文顺序呈现，不使用 description 代替正文，也不自动生成摘要。
- 文章标题与晓灰站点标识始终保留。署名只来自文章已有的 `frontmatter.author`，支持字符串或字符串数组；不把 SEO 元数据里的站点名后备值当作作者。
- 长图保留正文 DOM 的段落、显式换行、强调、行内代码、代码高亮与缩进、嵌套列表、引用、图片、KaTeX 公式和表格。内容适配画布高度，约 800 字是自然内容块收尾的参考，不要求在固定字符处截断。额外的高度保护用于极长段落、代码和特殊内容。
- 未展示完时，渐隐只覆盖正文结尾，并附继续阅读提示。下方独立的二维码、阅读全文提示及站点信息保持清晰，二维码指向当前页面 canonical URL。底部参考二维码短卡，使用左二维码、右文字的紧凑排版；不打印冗长的原文 URL。
- PNG 通过固定版本 `modern-screenshot` 在浏览器本地生成，不上传正文。颜色、字体取自 `quartz/design/tokens.ts`；导出采用浅色纸感，便于跨应用阅读。代码用等宽字体；正文用 CJK 友好字体。
- 预览按面板宽度展示，长图通过面板纵向滚动阅读，不把整张长图缩进一个固定高度的小框。

## 生命周期与回退

- 每种版式独立缓存，一篇文章最多保留两张图片；重复选择复用结果。
- 切换版式、关闭或重新打开面板、触发新操作后，较早的异步完成不能覆盖当前预览、状态或触发迟到的下载。
- 生成失败不会永久缓存失败结果，保存或切换版式可以重试；复制链接始终可用。
- 只有已缓存的图片可在用户点击的同步激活期间尝试系统分享。生成尚未完成、系统不支持、微信内浏览器或系统分享失败时，显示图片供保存或长按。取消系统分享不视为成功。
- SPA 离开文章时清理监听器、面板与对象 URL。离开后才完成的图片也立即释放。

## 验证

自动测试通过 `npm test` 执行，包括长图内容与排版边界、实际 SSR 署名和真实 inline 脚本的异步生命周期。设计契约与类型/格式检查仍使用 `npm run check:design` 和 `npm run check`。

`npm run test:share-browser` 使用 Chromium 与 WebKit 对真实组件执行浏览器验收，解码导出的 PNG 二维码并保存 320px / 390px / 桌面截图。首次运行需要 `npx playwright install --with-deps chromium webkit` 和可显示中文的字体。CI 在独立只读 Ubuntu 作业运行这些测试并上传 `share-posters-<browser>-<SHA>` 证据，不部署网站。详情见 [浏览器测试说明](../tests/browser/README.md)。

真实浏览器还应检查：

1. 短文、接近阈值、超长文章与超长单段，中文与混合文本。
2. 小标题、嵌套列表、引用、代码与特殊内容无重叠、溢出或字符裁切。
3. 320px、390px 和桌面面板；浅色和深色页面上的预览与键盘焦点。
4. 两种图片的保存、系统分享/取消与不支持时的回退。
5. 反复切换、关闭重开、生成失败后重试和 SPA 离开。
6. 实际导出 PNG 的正文可读性、清晰的阅读全文区域，以及二维码解码结果等于 canonical URL。

## DOM 导出方案（2026-10-10）

生产长图使用 `modern-screenshot 4.7.0`（MIT），保留文章 DOM，并应用分享容器的纸感阅读样式。
截取、署名、渐隐和二维码是项目自己的业务规则；文字、列表、公式及表格排版交给浏览器，
不再实现另一套 Canvas 文本排版引擎。原有短卡、缓存、下载、系统分享及 SPA 生命周期继续共用。

选型使用此前真实《DDD》的有界 PoC 以及官方源码，而非星数：

| 方案                                                                                | 核实结果与取舍                                                                                                                                                                                                 |
| ----------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [html-to-image 1.11.13](https://github.com/bubkoo/html-to-image/tree/v1.11.13)      | MIT；官方 CHANGELOG 日期 2025-02-14。既有真实文章 PoC 成功，通过 SVG foreignObject 复用浏览器 DOM/CSS；首轮 Chromium 通过，WebKit 在图片尺寸、解码正常时仍漏绘真实原图，不能作为本次跨浏览器生产路径。         |
| [modern-screenshot 4.7.0](https://github.com/qq15725/modern-screenshot/tree/v4.7.0) | MIT；2026-04-16 发布，维护更活跃、扩展接口更多，但默认占位与嵌入任务错误捕获同样不能保证资源完整。源码对 Safari 内联 dataURL 图片提供 SVG 解码重绘处理；据首轮真实图片失败改用此单一 SDK，并保留严格资源预检。 |
| [html2canvas 1.4.1](https://github.com/niklasvh/html2canvas/tree/v1.4.1)            | MIT；2022-01-22 发布。既有 PoC 成功，但自行实现 CSS 子集，不适合作为公式与复杂排版的主路径；不增加未经验证的双库回退。                                                                                         |

旧 PoC 结果保留在 [share-renderer-poc.json](./share-renderer-poc.json)。两种库的全文字符数受
动态 Mermaid 渲染时点影响，不能据此比较质量；有界版本均为 943 字符、约 4016px。
这些旧结果只证明当时 Chromium 中的可行性，不替代当前实现的真实文章和跨浏览器验收。

后续 CI 的同 DOM 对照发现，`html-to-image` 在 WebKit 中会漏绘《vector-database》的
Euclidean 原图，尽管资源已解码、元素尺寸与 Chromium 一致。`modern-screenshot` 的
[图片处理](https://github.com/qq15725/modern-screenshot/blob/v4.7.0/src/embed-image-element.ts)与
[SVG 绘制](https://github.com/qq15725/modern-screenshot/blob/v4.7.0/src/image-to-canvas.ts)包含
对应的 Safari 处理；此次仅替换最终光栅化调用，不并存两套 SDK，也不自行增加固定延时重试。
最终可用性仍以同一提交的真实 PNG、二维码和图像像素验收为准。

### 资源与边界

两种 DOM 截图库的资源代码都会吞掉部分下载失败或绘制错误，因此不能把 SDK Promise 完成
当成资源齐全的证据。导出前由应用明确等待、校验并内联所需图片与字体，失败显示可重试的
资源错误，不无声漏图。只请求文章已有资源，不上传正文、不使用截图服务或跨域代理。
第三方服务器不允许浏览器读取时会明确失败；SDK 不能绕过 CORS。
现有 Assets 构建管线会发布 `content/` 内的本地图片，分享图可直接复用这些同源资源；
它不会下载或缓存外链图片，本次也不新增图片代理或迁移文章资源。

约 800 字在自然内容块附近收尾，超长单段保留内联结构并按句子或完整字素边界截取。
图片和结构化内容保留原节点；高度保护与渐隐只作用于正文。预览仍可纵向滚动。
长代码通过 CSS 折行保留缩进与高亮；表格按手机宽度适配，不能通过横向裁切隐藏单元格。
二维码保留完整 canonical URL、足够 quiet zone 和可解码的输出尺寸。
当前会明确拒绝无法清晰适配的超宽公式、带合并单元格的宽表格，以及 SDK 无法可靠内联的 SVG CSS 遮罩；
不会把这些内容静默丢弃后报告导出成功。普通三列以内表格保留合并关系，较宽的简单表格按行适配。

### 验证方式

单元测试验证 DOM 结构与安全摘录、完整字素、自然块边界及错误恢复；真实浏览器测试验证
实际 PNG、资源失败、同源与真实跨源 CORS、公式字体、图片像素、二维码及全部分享生命周期。
真实样本包含《DDD》与《vector-database》。若为覆盖后部公式、表格或图片而导出文章节选，
验收证据会明确标注节选来源，不冒充全文开头。受 CORS 限制的真实图片可使用记录来源与 SHA256
的原字节同源测试样本；其成功不代表原图片域名允许 CORS。

Chromium 与 WebKit 的测试结果需分别记录；WebKit 自动化不等同于 iPhone 微信或真实 OS
分享面板验收。版本与环境限制、最终 SHA 的 CI 结果及实际 PNG 随 PR 提供。
