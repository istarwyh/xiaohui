生成式大语言模型读到：

```text
北京是中国的
```

它要从词表里预测下一个 `token`，答案是“首都”。

向量模型读到：

```text
查询：怎样给 PDF 设置密码？
相关文档：给 PDF 文件添加打开密码
困难负例：忘记 PDF 密码后如何解除
```

它不续写文字，只需要让查询更接近相关文档，远离那个看起来很像、实际解决另一件事的负例。

两边使用的底层计算并没有相差到两个世界。文本都会先变成数字，数字经过多层神经网络得到预测，训练程序再计算误差、反向传播并修改参数。真正把它们训练成不同工具的，是训练数据怎样出题，以及损失函数怎样判错。

本文比较两类常见模型：一类根据左侧文本预测下一个 `token`，一类把整段文本压成单个向量，再学习哪些文本应该靠近。

很多向量模型并不从随机参数开始。它们先继承语言模型已经学到的文本表示，再用大规模文本对训练“哪些内容应该靠近”。下文所说的向量模型预训练，主要指后一阶段；多向量检索和稀疏向量模型不在这次比较范围内。

## 预训练不是把答案写进模型

模型可能有数千万到数百亿参数。参数就是大量可调整的数字：有些把 `token` 编号变成初始向量，有些结合上下文更新向量，有些把最终结果变成预测分数。生成式语言模型还需要词表输出层，向量模型则可能增加池化或投影层。

训练不会找到“北京”对应的参数，然后把“首都”写进去。整个训练由大量参数更新组成，一次更新只让参数移动很小一步：

1. 取出一批训练数据；
2. 模型根据当前参数计算结果；
3. 损失函数把结果压成一个表示错误程度的数；
4. 反向传播计算哪些参数让错误变大或变小；
5. 优化器把相关参数移动一点点。

一轮调整之后，模型通常仍然会犯错。相似的规律在海量文本中反复出现，参数才慢慢形成稳定倾向。

为了看清调整方向，先用一组简化数字示意。真实训练中，单次更新造成的变化通常更小，也不会只影响这一句话。模型看到“北京是中国的”，给出下面的概率：

```text
首都：10%
城市：35%
地方：20%
其他：35%
```

正确答案“首都”只有 10%，损失会比较大。反向传播发现，如果稍微调整某些嵌入、注意力和输出层参数，“首都”的概率就会上升。优化器只改动很小一步。以后模型再次遇到相近上下文，概率可能变成：

```text
首都：18%
城市：30%
地方：17%
其他：35%
```

这还不够好，但方向对了。模型继续读到“中国的首都是北京”“法国的首都是巴黎”“某国的首都位于……”等文本，城市、国家和首都之间的关系会在许多参数中逐渐稳定下来。

预训练留下的是一套参数，不是一份可以直接打开的知识表。

## 文本进入模型后，先不再是文字

神经网络不能直接对汉字做矩阵乘法。文本会先经过 `Tokenizer`，被切成 `token`：

```text
北京 / 是 / 中国 / 的 / 首都
```

这里只按词展示。实际怎样切分取决于模型的 `Tokenizer`，一个词可能对应一个或多个 `token`。每个 `token` 在词表里有一个编号。下面的数字只用于示意：

```text
北京 → 8312
是   → 247
中国 → 3021
的   → 19
首都 → 9276
```

编号只负责找到对应项目。8312 并不比 247“更有语义”。模型使用编号去嵌入表里查出一串可训练的浮点数：

```text
北京 → [0.12, -0.31, 0.08, ...]
是   → [-0.07, 0.21, 0.44, ...]
中国 → [0.35, -0.16, 0.09, ...]
```

这串数字才是进入 `Transformer` 的初始向量。4096 维可以先理解成模型为一个 `token` 保留了 4096 个记录位。它们不是人工指定的“词性位”或“地点位”，单独看某一维通常没有明确含义。

假设一句话有 5 个 `token`，每个向量有 4096 维，`[5, 4096]` 就表示 5 个位置各自带着 4096 个数字。每层 `Transformer` 都读取这组向量，再输出一组更新后的向量。形状通常不变，但每个位置的数字会根据周围 `token` 重新变化。某一层计算结束后留下的这组数字，就是这一层的隐藏状态。“苹果公司发布手机”和“把苹果削皮”中的“苹果”起初可能查到相同嵌入，经过上下文计算后会得到不同状态。这个过程在 [[Transformer|向量为什么能够表示语义]] 中有更完整的展开。

生成式大语言模型和向量模型此时都在处理一组 `token` 向量。它们会用不同方式读取这些隐藏状态，也会用不同答案计算损失。

## 大语言模型怎样完成一次预训练

### 一段文本会变成很多道题

假设训练文本是：

```text
北京 是 中国 的 首都
```

它不会只产生一道“的后面是什么”的题，而会同时产生多道题：

```text
看到“北京”              → 预测“是”
看到“北京 是”           → 预测“中国”
看到“北京 是 中国”      → 预测“的”
看到“北京 是 中国 的”   → 预测“首都”
```

实际训练会把输入和答案错开一位：

```text
输入：北京  是    中国  的
标签：是    中国  的    首都
```

`Transformer` 可以并行计算这些位置，但因果掩码不允许前面的位置偷看右侧答案。预测“中国”时，只能读取“北京 是”；预测“首都”时，可以读取“北京 是 中国 的”。

一段 2048 个有效 `token` 的序列，大致能提供 2047 个下一个 `token` 预测位置。这也是语言模型可以从原始文本中获得密集训练信号的原因。网页、书籍和代码不需要人工逐句写答案，向右错开一位就有了监督目标。

### 隐藏向量还要经过词表输出层

假设最后一个位置的隐藏向量有 4096 维：

```text
[0.17, -1.23, 0.48, ...]
```

它还不是 `token`。模型使用词表输出层，把 4096 个数字映射成与整个词表一样长的一组分数。如果词表有 10 万个 `token`，输出就是 10 万个 `logits`：

```text
首都 → 2.1
城市 → 3.4
地方 → 2.8
……
```

`logits` 只是未经归一化的分数。经过 `Softmax` 后，它们才变成总和为 100% 的概率。训练程序检查正确答案“首都”的概率。如果正确答案概率很低，损失就高；概率接近 100%，损失就低。

这里使用的判分方法叫交叉熵。读者只需先抓住它的方向：模型给正确答案的概率越低，惩罚越大；概率越高，惩罚越小。所有有效预测位置的惩罚取平均，就得到这批文本的损失。训练会持续尝试降低这个数。

### 反向传播到底做了什么

前向计算留下了一条完整路径：哪个 `token` 查了哪条嵌入，经过哪些注意力和前馈网络，最后怎样影响“首都”的概率。

反向传播沿这条路径倒着计算：如果某个参数增加一点，损失会上升还是下降，变化有多大。这个变化率叫梯度。

优化器读取梯度后更新参数：

```text
新参数 = 旧参数 - 学习率 × 梯度
```

学习率控制步子大小。步子太大，模型可能越过合适位置，训练震荡；步子太小，训练速度很慢。真实训练还会加入控制更新速度和数值稳定性的措施，但没有改变“前向计算—损失—反向传播—参数更新”这条链路。

一次更新不仅会改词表输出层。只要参数没有被冻结，梯度会继续传到每层 `Transformer` 和嵌入表。模型因此调整的不只是“首都”这个词的分数，还包括怎样读取“中国”、怎样组合“国家—首都”关系，以及哪些上下文对当前预测更重要。

### 预测下一个 `token` 为什么会学到语义

前面的两个“苹果”之所以会形成不同隐藏状态，是因为它们后面可能出现的词不同。要分别预测“发布”和“削皮”，模型必须利用“公司”“吃”等上下文，不能只记住单词编号。

如果后面的代码再次使用前面定义的变量，模型只有保留变量关系，才更容易预测正确内容；如果长文章再次提到某个人物，它也需要利用前文信息判断接下来更可能出现什么。复杂表示是在这些预测压力下逐渐形成的，但训练目标不保证模型真的理解或推理正确。

这套目标仍然有明显边界。交叉熵只检查下一个 `token` 的概率，不直接验证事实真假，也不检查生成内容能否在现实中执行。模型可能学会流畅地复述错误材料。

## 向量模型怎样完成一次对比训练

向量模型不需要从词表里挑出下一个 `token`。它要把长度不同的文本变成长度相同、可以比较距离的向量。

### 多个 `token` 向量怎样压成一个向量

假设“给 `PDF` 设置密码”被切成 5 个 `token`。经过 `Transformer` 后，每个位置都有自己的隐藏向量：

```text
PDF    → [0.21, -0.14, ...]
设置   → [0.08,  0.37, ...]
密码   → [0.44, -0.09, ...]
……
```

检索系统需要给整句话建立一个索引，不能把数量不定的 `token` 向量直接当作一条固定长度记录。模型要执行一次池化。常见做法包括：

- 读取一个特殊位置的向量；
- 读取最后一个有效 `token` 的向量；
- 对所有有效位置做平均；
- 用可训练的注意力池化决定不同位置的权重。

平均池化可以想成把每一维分别求平均。为了方便展示，假设三个 `token` 只有二维：

```text
[1.0, 0.2]
[0.4, 0.8]
[0.7, 0.5]
```

第一列的三个数平均为 0.7，第二列平均为 0.5，最后得到：

```text
[0.7, 0.5]
```

真实模型会有几百或几千维。池化后还可能经过投影层，把隐藏维度从 4096 变成 1024；归一化再把向量长度调整为 1，方便比较两个向量的方向是否接近。

因此，无论输入是 10 个还是 500 个 `token`，模型最终都可以输出 1024 维向量。1024 是架构规定的输出尺寸，不是训练数据为每句话准备了 1024 个正确数字。

### 训练数据只告诉模型谁更相关

还是看这组三元组：

```text
Query：怎样给 PDF 设置密码？
Positive：给 PDF 文件添加打开密码
Hard Negative：忘记 PDF 密码后如何解除
```

三段文本可以交给同一个编码器处理；有些模型也会分别处理查询和文档。无论采用哪种结构，最后都会得到三个长度相同的向量：

```text
q  = Query 的向量
p  = Positive 的向量
n  = Hard Negative 的向量
```

训练程序再计算相似度。相似度不是“相关概率”，只是按同一套规则得到的比较分数，通常越大表示两个向量的方向越接近。不同模型的分数范围可能不同，这里只比较同一组候选里谁高谁低。

假设训练刚开始时得到：

```text
相似度(q, p) = 0.42
相似度(q, n) = 0.51
```

模型把“解除密码”排在“设置密码”前面，顺序错了。对比损失会变大。反向传播沿着生成这些向量的计算过程往回找：哪些参数让错误文档得分过高，哪些参数让正确文档得分过低。优化器随后把这些参数调整一点。

训练一段时间后，分数可能变成：

```text
相似度(q, p) = 0.83
相似度(q, n) = 0.27
```

这里没有哪一个 1024 维数组被指定为标准答案。训练要求正例相对负例取得足够明显的优势：有的损失看正例在一批候选中的概率，有的损失要求正负分数至少拉开一段距离。另一次独立训练可能得到完全不同的坐标，只要文本之间的相对关系满足任务要求即可。

### 对比损失怎样同时处理一批样本

实际训练不会一次只比较三句话。假设一个批次有四组查询和相关文档：

```text
q1 → d1
q2 → d2
q3 → d3
q4 → d4
```

模型会计算每个查询与每篇文档的相似度，形成一个 4×4 的表：

```text
          d1    d2    d3    d4
q1       0.8   0.2   0.1   0.3
q2       0.4   0.9   0.2   0.1
q3       0.1   0.3   0.7   0.4
q4       0.2   0.1   0.3   0.8
```

对角线是配对正例。其余位置可以直接作为批内负样本，这样一次编码就能产生许多比较关系。常见的 `InfoNCE` 损失会提高对角线分数，同时压低同一行其他位置的分数。

这种做法便宜，却会遇到假负例。假设 `d2` 其实也能正确回答 `q1`，训练程序仍可能把它当作负例推远。数据表里的“不是配对项”不等于语义上的“不相关”。多正例、重复文档和近义问题需要额外标记或屏蔽。

### 为什么困难负样本很重要

随机找一篇“怎么养猫”作为“`PDF` 加密”的负例，模型很快就能区分，继续训练也学不到细边界。

“忘记 `PDF` 密码后如何解除”包含相同对象和大量相同词，却与“设置密码”方向相反。这样的困难负例会迫使模型区分动作、条件和意图，而不是只看关键词重合。

负样本也不能难到标错。一个同时适用于查询的文档被当成负例，梯度会坚定地把正确内容推远。向量训练中，数据质量很大一部分就藏在正负关系是否可靠。

### 向量空间里的“相关”由任务决定

“苹果”和“香蕉”在水果分类里很接近；在手机检索里，“苹果”和“华为”可能更接近。两套向量都可以有用，只是服务的任务不同。

问答检索希望问题靠近答案，商品召回希望需求靠近商品，代码搜索希望自然语言靠近代码片段，同义句任务则希望不同表达互相靠近。训练数据把什么标成正例，向量空间就会优先保存什么关系。

## 把两次训练逐步放在一起

| 训练环节 | 生成式大语言模型 | 向量模型 |
| --- | --- | --- |
| 原始材料 | 网页、书籍、代码等连续文本 | 查询—文档、句子对、标题—正文等关系数据 |
| 模型读到的输入 | 一段 `token` 序列 | 两段或多段 `token` 序列 |
| `Transformer` 输出 | 每个位置一个隐藏向量 | 每段文本的多个隐藏向量 |
| 任务读取方式 | 每个位置接词表输出层 | 池化成固定长度向量 |
| 模型要答的题 | 下一个 `token` 是什么 | 哪段文本更相关 |
| 损失检查什么 | 正确 `token` 的概率 | 正例与负例的相对相似度 |
| 反向传播修改什么 | 未冻结的嵌入、`Transformer`、词表输出层 | 未冻结的编码器、投影层和可训练池化层 |
| 直接得到的能力 | 根据上下文继续生成 | 根据向量距离检索或匹配 |

直接拿生成式大语言模型的某一层隐藏状态做平均，虽然也能得到固定向量，却不一定适合检索。语言模型训练时没有被明确要求“同义句的最终向量要接近”，专门的向量训练补上了这条约束。

## 向量模型为什么经常继承语言模型底座

如果向量模型从随机参数开始，既要学会词语、语法和上下文，又要学会怎样排列相关文本。对比数据提供的监督通常没有连续文本密集：一段长文本能产生许多下一个 `token` 预测位置，一组检索数据只提供有限的相关关系。

一种常见做法，是先继承已经完成语言模型预训练的底座。`BERT` 类模型会遮住句子中的一部分 `token`，再根据两侧内容把它们猜回来；生成式语言模型则预测下一个 `token`。两条路线都能先获得词法、句法和上下文表示。

随后，查询、问答、标题—正文、同义改写和代码说明等大规模文本对继续训练整段表示。这一步常被称为向量模型的通用对比预训练。进入具体业务后，还可以补一轮高质量领域数据，重新收紧“相关”的边界。这些阶段可能被省略或合并，并不是每个模型都遵循固定三段式。

在保险推品中，疾病名称的不同表达可以保持接近，险种变化却可能改变推荐结果；在代码搜索中，函数作用比变量名是否相同更重要。具体样本与 `InfoNCE` 的工程实践见 [[embedding-training-for-qq-matching|保险推品中的语义匹配：从产品池复用到领域微调]]。

后续训练可以修改全部参数，也可以冻结大部分底座，只训练投影层或少量新增参数。这会影响成本和模型能被调整的幅度，不会改变正负样本所定义的训练方向。

## 训练损失下降，还不能证明模型可用

语言模型在训练集上的损失下降，可能只是记住了重复文本。向量模型的正负样本如果按同一模板生成，再随机分到训练集和评测集，模型也可能靠模板取得漂亮分数。

数据最好按文档来源、时间、用户或近重复簇隔离。语言模型还要观察留出集损失、困惑度、下游任务和实际生成行为。向量检索则需要结合任务选择指标：

- `Recall@K` 检查相关文档是否进入前 K 个候选；
- `MRR` 关注第一个正确结果排在多前；
- `nDCG` 适合存在多个相关等级的结果；
- 商品推荐、代码搜索和业务问答还要检查最终返回内容是否真的可用。

[[vector-database|向量数据库]] 负责在已有向量中快速查找和过滤。它可以加快检索，却不能修正训练数据里标错的正负关系。训练日志中的损失下降，也只说明模型越来越会做训练题；向量模型是否可用，最后还得拿真实查询去看，正确文档究竟有没有出现在前几个结果里。
