# 智能体系统写作计划

我本来也不买技术书。因为网上什么都有。直到我发现，问题不是资料不够，而是资料不会替我工作。

一个工程师现在需要的，可能不是再买一本工具说明书，而是一套能进入他的项目、读他的文件、跑他的测试、记住他的偏好、拦住他的低级错误的工作环境。

这也是我做 `CC4PM` 和继续研究 `Agent Runtime` 的原因：知识不应该只被阅读，它应该能被安装、触发、执行、审计和演化。

## 不写什么

这本书不应该写成 `Claude Code` 使用手册。工具教程太浅，寿命也短。按钮、命令、模型、平台都会变。

也不应该写成又一本泛泛的 `AI Agent` 入门书。市面上已经有很多书在讲 `LangChain`、`LangGraph`、`AutoGen`、`CrewAI`、`Dify`、`Coze`、`MCP`。如果只是把这些名词整理一遍，没有必要再写。

更不应该写成“我在大厂的一线经验”。我现在在蚂蚁集团，所有内容都必须和公司内部项目、业务数据、架构、工具、客户、流程保持干净边界。蚂蚁只能作为职业背景存在，不能作为素材来源。

## 真正要写什么

我想写的是智能体系统建设。

更具体一点：从 `Agent Protocol` 出发，从零实现一个可恢复、可观测、可评测的 `Agent Runtime`。

如果以前介绍 `Spring` 的书不是教人写 `Java`，而是教人理解容器、生命周期、依赖注入、拦截器、事务、测试和部署，那么这本书也不应该教人“怎么写一个聊天机器人”。它应该讲：

- `Agent Runtime` 的核心对象是什么
- 一次任务如何从输入变成 `Run`
- `Step` 如何推进
- `Event` 如何流出
- `Artifact` 如何成为正式产物
- `Checkpoint` 如何让任务恢复
- `interrupt / resume / cancel / retry` 如何成为协议动作
- 工具、模型、记忆、评估、权限、观测如何被组织起来

`Harness Engineering` 可以成为其中一章，但不应该成为整本书的唯一标题。它更像模型之外的控制层。

## 目标形态

这不是一本单独的书，而是一套组合：

- 书：讲判断、架构、取舍、失败和方法
- `Python` 参考实现：证明这套抽象能跑
- `Jupyter Notebook`：让读者一步步看见生命周期
- `GitHub` 仓库：放代码、测试、实验和版本历史
- `Skill`：未来可以把书的部分内容做成可执行教学

书是地图，代码是骨架，`Notebook` 是实验台，`Skill` 是进入工作现场的入口。

## 最小对象模型

第一版只围绕六个对象展开：

| 对象 | 含义 |
| --- | --- |
| `Thread` | 长期对话或任务上下文的边界 |
| `Run` | 一次可审计的执行 |
| `Step` | 一次模型调用、工具调用、人工确认或子任务 |
| `Event` | 可流式观察的状态变化 |
| `Artifact` | 任务正式产物，比如报告、文件、代码 diff、图表 |
| `Checkpoint` | 可恢复的状态快照 |

先把这六个对象跑通，再谈 `MCP`、`A2A`、`AG-UI`、多智能体和复杂编排。

## 构建式学习

我现在也不是完全想清楚了。这个计划不能建立在“我已经是专家”的假设上。更好的方式是边做边学。

每个阶段产出三样东西：

- 一段可运行代码
- 一个 `Notebook`
- 一篇文章

文章的形式可以是“我原来以为 vs 现在发现”：

- 我原来以为 `Run` 只是一次模型调用，后来发现它是权限、成本、超时和审计的边界
- 我原来以为流式输出就是 `token`，后来发现生产系统真正需要的是事件流
- 我原来以为 `Memory` 很重要，后来发现 `Checkpoint` 比 `Memory` 更基础
- 我原来以为多智能体是重点，后来发现单个 `Runtime` 的生命周期不清楚，多智能体只会更乱

## 三个月实验计划

先不急着承诺完整书稿。用三个月做公开学习工程。

### 第 1-2 周：生命周期

- 实现 `Thread / Run / Step / Event`
- 使用 `SQLite` 做最小持久化
- 写 `01_runtime_lifecycle.ipynb`
- 文章题目：`Run` 为什么不是一次模型调用

### 第 3-4 周：事件流与产物

- 实现事件追加和订阅
- 实现 `Artifact` 保存
- 写 `02_event_stream.ipynb` 和 `03_artifact.ipynb`
- 文章题目：流式输出不等于事件流

### 第 5-6 周：工具调用

- 实现 `Tool Registry`
- 支持本地函数工具
- 记录工具输入、输出、错误和重试
- 文章题目：工具调用的协议边界

### 第 7-8 周：中断与恢复

- 实现 `Checkpoint`
- 实现 `interrupt / resume / cancel`
- 写 `04_checkpoint_resume.ipynb`
- 文章题目：`Checkpoint` 比 `Memory` 更基础

### 第 9-10 周：评估与审计

- 实现最小 `Eval Harness`
- 记录成本、耗时、步骤数和失败原因
- 文章题目：不要让智能体自己判断自己完成了

### 第 11-12 周：外部协议映射

- 对照 `MCP`、`A2A`、`AG-UI`、已有 `Agent Protocol`
- 不急着完整实现，先画出对象映射和差异
- 文章题目：框架会变，协议对象不会变

三个月后再决定是否正式签书稿。到那时，手上应该有一个仓库、六个 `Notebook`、八到十篇文章、一套术语表和一张架构图。那时再谈出版，就不是空想。

## 判断标准

这件事能不能继续，不看出版社是否催，不看热点是否还热，看三个东西：

- 这个 `Runtime` 是否真的能跑
- 文章是否写出了我自己理解变化的过程
- 读者能不能跟着代码和 `Notebook` 复现

如果做不到，就继续学习，不急着写书。

如果做到了，书只是这个系统的叙事层。
