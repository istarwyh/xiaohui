# Writing Rules

## 核心原则：吸收是化学反应，不是搬运

每次 absorb 是新输入与已有内容的化学反应。你不是归档员，你是帮助作者**内化**的思考伙伴。

1. **消化**：理解输入的核心洞见，用作者的语气重新表达，而不是原封不动粘贴。
2. **关联**：搜索已有内容，找到可以连接、呼应、对比的观点，用 `[[wikilink]]` 编织成网。
3. **重组**：如果新旧内容放在一起能产生更深的结构，就打散原有组织，重新编排——合并、拆分、重构都可以。
4. **升华**：加入个人视角和判断。最终产物应该比原始输入更有深度，让读者感觉这是作者自己想出来的东西，而不是"引用了一段话"。

不一定每次都要产出独立文章。吸收可以是对已有内容的再梳理——新旧材料发生化学反应后，原有笔记被改写、重组、升级。

## 文章不是资料的陈列柜

输入里常常同时有事实、例子、反例、背景知识和几种可能的解释。不要因为它们都相关，就让它们依次获得一个段落。覆盖得完整，通常只证明资料来过，没有证明作者完成了选择。

先找到材料里真正让人停下来的那处不协调：一件东西为什么变了，一句判断为什么和直觉冲突，一个旧解释为什么不再够用。文章跟着认识的变化往前走。下一段可以把判断推深，可以让它碰壁，可以换一个角度使前面的东西突然变样；不能只是再提供一个同类对象。

同一结论下面如果有三个例子，通常只需要写透一个。第二个例子只有在它会改变、限制或反驳原判断时才值得展开。其余材料可以缩成一句，也可以完全不用。作者的工作不只是找到材料，还要决定哪些材料不进入文章。

不要把这种组织方式再做成一套显眼的模板。不要要求每节固定包含问题、主张、案例、反例和总结，也不要让所有章节长度相近、结构对称。内部可以有计划，成文时要让脚手架退下去。读者应该遇见一个判断怎样被逼出来，而不是看见作者填写过哪些栏目。

比较好的段落关系，往往是读到下一段之前未必猜得到，读完以后又觉得它只能出现在这里。

## 留白不是缺少内容

读者能从物件、动作和前后位置里跨过去的地方，不要替他搭一座写着结论的桥。一个细节已经让判断成立，就别再补一句 `这说明`；一个比喻已经抵达，就别解释它对应什么；一个反例已经刺破前文，就允许段落在那里停一下。

留白不只是多一个空行。它来自克制：少解释半步，不把每个疑问当场回答，不在每节末尾回收结论，不急着把暧昧处理成态度。文章可以有短段、突然转向和没有被抚平的边缘。读者参与完成的那一步，也是阅读发生的地方。

## 删除是在完成判断

正确、好看、查证过的内容也可以删除。删掉一段不会损失认识，只会损失“我还知道这些”的展示，那一段就不该留下。

尤其警惕这些材料：为了覆盖主题而加入的第二、第三个同类例子；只证明做过搜索的知识；给相邻段落复述共同点的总结；提前解释后文的路标；已经被场景表达过一次的抽象判断；为了让结尾完整而抬高的话。

不要用更多标题、表格、过渡句和总结去挽救没有运动的文章。先删掉并排摆放的信息，再看剩下的材料之间是否真的有张力。有时整节只剩一个物件和一次转折，反而够了。

## 写作风格

- 用作者的语气和判断，不是用第三人称转述。
- 简洁有力，有比喻和意象。
- 平衡客观推理与主观洞见。
- 以中文为主，英文术语用反引号包裹。
- 允许适当跳跃和留白。不要为了模型以为的通顺，补 `这说明...`、`由此可见...`、`关键在于...`、`这个组合有意义` 这类黏合句。过渡句如果没有带来新对象、新动作、新成本或新判断，直接删。
- 不要按名词逐项介绍。段落的先后由认识如何变化决定，不由资料可以分成几类决定。
- 观察、假设、验证，验证不了就保持怀疑。不要把线索写成结论，不要把反例写成反证，不要为了收束把“可能”压成“必然”。

## 文件格式

- 使用 Markdown，新建文章时包含 YAML frontmatter (`title`)。
- 使用 Obsidian `[[wikilink]]` 做交叉引用。
- 英文技术术语用反引号包裹。

## 合入已有文章时

- 找到最佳插入点，但**不要只是追加**——考虑新内容是否改变了原有段落的逻辑，是否需要重排。
- 只在必要时添加过渡句。不要为了让新旧内容显得顺滑而塞入空泛解释；读者可以自己跨过的地方，留白比黏合剂更好。
- 为新的连接点添加 `[[wikilinks]]`。
- 如果新内容让原文的某段变得多余或矛盾，可以修改或删除。

## 新建文章时

- 给文件一个有意义的名称。
- 技术主题优先用英文加连字符命名，生活/社会/随笔用中文命名。
- 链接到相关已有文章。
- 如有必要，在文末加 `Related` 小节。

## 更新 `journey.md` 时

- 保持条目精选、高信号，不要每条都加。
- 放在正确的年份或人生阶段下。
- 优先使用简短段落或 1-3 条要点。
- 用 `[[wikilink]]` 链接到深度文章。

每条里程碑应直接或间接回答：

- 发生了什么？
- 为什么重要？
- 能力、责任、身份或信念发生了什么变化？
- 读者在哪里可以看到更深层的记录？

推荐形式：

```md
- [事件/角色/项目]：这件事让我从 [旧阶段] 进入 [新阶段]，开始真正关注 [能力/判断/方向]。相关记录：[[文章名]]
```

## 更新 portfolio/profile 页面时

- 使用具体证据：指标、角色、责任、交付物、奖项名称、公开链接。
- 避免过度推销，用事实说话。
- 如果同一事件也对成长有意义，在 `journey.md` 中只加简短指针。
